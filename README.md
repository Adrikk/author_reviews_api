# Pet FastAPI CRUD

Учебный REST API для каталога авторов, книг и отзывов. Проект нужен для практики
FastAPI, Pydantic, SQLAlchemy, Alembic, разделения приложения на слои и тестирования.

Это заготовка бэкенда, а не готовый публичный сервис: авторизации и проверки
владения записями пока нет. Клиент передаёт `author_id` при создании книги и
отзыва, поэтому API пока не следует выставлять в интернет без дополнительных
ограничений.

## Возможности

- CRUD для авторов и книг; отзывы можно создавать, читать, обновлять и удалять
  в контексте книги.
- Книги создаются скрытыми (`is_shown=false`), пока автор не решит их показать.
- В публичных списках книг и отзывов отображаются только записи с `is_shown=true`.
- Рейтинг книги пересчитывается по показанным отзывам.
- Ошибки приложения преобразуются в HTTP-ответы; изменения схемы БД ведутся
  миграциями Alembic.

## Структура проекта

```text
.
├── main.py                 # Создание FastAPI-приложения и подключение роутеров
├── schemas.py              # Схемы запросов и ответов Pydantic
├── models.py               # ORM-модели SQLAlchemy
├── database.py             # Движок и фабрика сессий БД
├── dependencies.py         # Зависимости приложения, включая сессию БД
├── exceptions.py           # Исключения приложения
├── routers/                # HTTP-маршруты и преобразование запросов/ответов
├── services/               # Бизнес-правила и сценарии приложения
├── repositories/           # Запросы к базе данных
├── migrations/             # Миграции Alembic
└── tests/
    ├── unit/               # Изолированные тесты сервисов
    └── integration/        # Проверки API с временной SQLite
```

Путь запроса в общем случае: **router → service → repository → database**.
Роутер отвечает за HTTP, сервис — за правила приложения, репозиторий — за
операции с БД.

## Запуск локально

Нужны Python и установленные зависимости проекта: FastAPI, Uvicorn, Pydantic,
SQLAlchemy, Alembic, email-validator и pytest. После установки зависимостей из
активного окружения выполните из корня проекта:

```powershell
alembic upgrade head
uvicorn main:app --reload
```

По умолчанию используется SQLite-файл `redaction.db`. После запуска:

- API: <http://127.0.0.1:8000>
- Swagger UI: <http://127.0.0.1:8000/docs>
- ReDoc: <http://127.0.0.1:8000/redoc>

## Основные маршруты

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/authors` | Список авторов |
| `GET` | `/authors/{author_id}` | Автор по ID |
| `POST` | `/authors` | Создать автора |
| `PUT`, `PATCH`, `DELETE` | `/authors/{author_id}` | Заменить, изменить или удалить автора |
| `GET` | `/books` | Список опубликованных книг |
| `POST` | `/books?author_id={id}` | Создать книгу для автора |
| `PUT`, `PATCH`, `DELETE` | `/books/{book_id}` | Заменить, изменить или удалить книгу |
| `GET` | `/books/{book_id}/reviews` | Показанные отзывы к книге |
| `GET`, `PATCH`, `DELETE` | `/books/{book_id}/reviews/{review_id}` | Получить, изменить или удалить отзыв |
| `POST` | `/books/{book_id}/reviews` | Добавить отзыв к книге |

Точные схемы запросов доступны в Swagger UI.

## Тесты

Из корня проекта:

```powershell
python -m pytest -q
```

Юнит-тесты проверяют отдельные правила сервисов с подменёнными зависимостями.
Интеграционные тесты проходят через API и используют SQLite в памяти, не изменяя
локальную базу `redaction.db`.

## Как развивался проект

1. Начальная версия CRUD была сосредоточена в `main.py`.
2. HTTP-маршруты были вынесены в `routers/`, работу с БД — в `repositories/`.
3. Добавлен слой `services/` для бизнес-правил.
4. Добавлены модели авторов, книг и отзывов, миграции Alembic, фильтрация
   неопубликованных записей и базовые тесты.
